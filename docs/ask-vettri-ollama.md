# Ask Vettri with Ollama

Ask Vettri calls the configured Ollama server from the Spring Boot backend. The browser continues to use the authenticated Vettri API and never connects to Ollama directly.

## Local development

1. Install Ollama on the backend development machine and start the Ollama service.
2. Download the configured model, for example `ollama pull gpt-oss:20b`.
3. Start the backend with these environment variables (defaults are shown):

   ```text
   AI_PROVIDER=ollama
   OLLAMA_BASE_URL=http://127.0.0.1:11434
   OLLAMA_MODEL=gpt-oss:20b
   OLLAMA_TEMPERATURE=0.2
   OLLAMA_MAX_TOKENS=512
   OLLAMA_TIMEOUT_MS=60000
   ```

Ollama must be reachable from the backend process. If it is stopped or returns an invalid response, Ask Vettri uses its existing deterministic, permission-checked guidance; live data answers remain generated by Vettri services.

## Hosting and privacy

Install Ollama on a private backend host with enough memory and CPU/GPU capacity for the selected model. Do not expose Ollama's port to the public internet. Use private networking and firewall rules between the backend and Ollama when they run on separate hosts. Keep provider configuration in server-side environment variables; never place model credentials or the Ollama URL in frontend configuration.

The model receives a bounded message history, a small server-derived context (roles, available capabilities, permission scopes, and optional organizational labels), and authorized tool results. The self-service salary and payslip tools return only the signed-in employee's figures and are exposed only after the existing self-service permission and employee-scope checks pass. User, employee, and company identifiers are not included in model context. Tool selection is allow-listed by the backend and access is rechecked by the existing services and authorization rules. Do not send full employee records, document contents, or credentials to the model.

Because authorized tool results are included in the conversation sent to Ollama, run the model on a trusted private host and treat its conversation storage/logging according to the sensitivity of the user's HR data. Do not route this integration to a public or third-party model endpoint.

To verify native function calling against a running model, pull the configured model and run the opt-in integration test:

```powershell
$env:RUN_OLLAMA_INTEGRATION = "true"
$env:OLLAMA_MODEL = "gpt-oss:20b"
mvn "-Dtest=OllamaAssistantIntegrationTest" test
```

This integration test is not run by default and requires a reachable Ollama server with the selected model already available.
